# Menu-bar dashboard refresh

Status: critic cap reached — decompose: accessible chart pilot, then visual refresh

## Outcome

A person opening the popover should identify **what changed per day, over which days, and whether the current view is all workspaces or one** before reading the charts. In the user-supplied dark screenshot, the two large figures have only `/ DAY` and `/ 30D` as visible labels, four additional large totals compete with them, and the monthly legend requires decoding six keys across a narrow row. The screenshot was supplied in conversation, not checked into this public repository because it contains the user's local metrics. These observations also correspond to `DashboardView.swift:31-66,127-175,226-253` and `MomentumHero.swift:9-47,50-83`.

The collector, metric definitions, snapshot's public `metrics` array, menu-bar value, refresh lifecycle, and Settings window stay unchanged. The change is presentation only. The default width remains 430 points; content may scroll within the existing fixed-height popover rather than grow off-screen.

## Choice and alternatives

**Keep both analyses visible; repair hierarchy and explanations.** Label and weight the hero figures, turn the redundant four-number card into a source-with-breakdown summary, and give chart keys and annotations more legible structure. This preserves today's zero-click access to both charts. A tabbed analysis panel would offer a taller single chart but hides the other analysis, conflates distinct questions (source size and monthly churn) as interchangeable, and introduces view state and accessibility work without evidence that the current plot height is the principal failure. A separate full window is a larger product change. Styling only the existing unnamed figures leaves the redundant totals and legend crowding untouched.

## Interface

1. **Header.** Keep the title, scope chooser, timestamp, Refresh/Cancel, Settings, and Add in the fixed header. The scope title takes remaining width and truncates with a tooltip for the full name; title/actions/timestamp keep their space. Header actions retain native button behavior and gain keyboard focus and explicit accessibility labels. Status banners and refresh progress remain the existing single content channels; no duplicate status row is added. Existing empty, stale, error, partial, and refreshing states retain their messages.
2. **Hero.** In `MomentumHero`, show visible labels `SOURCE CHURN` and `NET SOURCE CHANGE` above their figures, with `last N closed days` context in the hero. Churn is the dominant high-contrast number, net change and its sparkline use neutral ink even when positive; a plus sign means lines added minus deleted, not a quality verdict. Each keeps its existing sparkline, open-day trailing segment, help definition and hover readout. Ensure its absolutely positioned hover card still clears the summary beneath it (`DashboardView.swift:114-117`, `MomentumHero.swift:239-253`). No metric or trend calculation changes.
3. **Composition.** Render `snapshot.metrics` differently without changing the public model: latest `Source` total followed by `Code` and `Tests` as components; `Docs` explicitly `separate`. The source total must not appear additive with all three other numbers. Use native text ink for values and small keyed marks for chart series, not colored numerals alone. Preserve `--` when unavailable and the aggregate cohort semantics from the snapshot.
4. **Charts.** Keep `SourceVolumeChart` and `MonthlyChurnChart` together in the scroll view and preserve axes, hover rows, series, and current partial period. Use readable headings (`Source lines over time`, `Monthly activity`) and short visible notes: docs below the axis are separate positive counts, not negative source lines; monthly bars are additions plus removals, not net growth. Reflow the six-item activity legend in two rows grouped by kind, with `Added` and `Removed` expressed in text, while retaining existing colors; the source legend remains aligned with its plot where it fits. Do not change the chart's numeric domain or fake negative documentation data.
5. **Accessibility.** Add an `AXChartDescriptorRepresentable` for each detailed chart using the existing timeline, with labels and series values corresponding to actual counts, not invented negative docs; verify Apple's Swift Charts integration in the Xcode SDK and with VoiceOver. Use a categorical date axis and nonnegative spoken docs values with an explicit summary that the visual docs band is drawn below the baseline only to separate it; the accessible series is a data representation, not a claim that docs LOC is negative. Apple's `AXChartDescriptorRepresentable` and `accessibilityChartDescriptor` compile with the installed Xcode SDK in a standalone probe. Maintain accessible summary labels for the hero's sparklines. The chart hover layer remains pointer-driven but does not gate data for assistive technology. No new data table UI or separate chart model is added.
6. **Footer.** Leave Remove and Quit as-is in this visual PR. Removing a workspace also deletes its saved report (`WorkspaceController.swift:130-133`), so a reassuring confirmation that only mentions source files would misrepresent the consequence. A truthful confirmation is a separate UX fix with its own review and real `LSUIElement` activation test, not part of this diff.

## Sequencing after critic

The independent final round requested decomposition, not another critique.

# Menu-bar dashboard refresh

Status: critic cap reached — decompose: accessible chart pilot, then visual refresh

## Outcome

A person opening the popover should identify **what changed per day, over which days, and whether the current view is all workspaces or one** before reading the charts. In the user-supplied dark screenshot, the two large figures have only `/ DAY` and `/ 30D` as visible labels, four additional large totals compete with them, and the monthly legend requires decoding six keys across a narrow row. The screenshot was supplied in conversation, not checked into this public repository because it contains the user's local metrics.

The collector, metric definitions, snapshot's public `metrics` array, menu-bar value, refresh lifecycle, and Settings window stay unchanged. The width remains 430 points. The user chose to keep both charts stacked: the popover grows to the scroll content's natural height when the display permits and caps its height to preserve the fixed header/footer on shorter screens; excess content scrolls.

## Choice and alternatives

**Keep both analyses visible; repair hierarchy and explanations.** Label and weight the hero figures, turn the redundant four-number card into a source-with-breakdown summary, and give chart keys and annotations more legible structure. This preserves today's zero-click access to both charts. A tabbed analysis panel would offer a taller single chart but hides the other analysis, conflates distinct questions (source size and monthly churn) as interchangeable, and introduces view state and accessibility work without evidence that the current plot height is the principal failure. A separate full window is a larger product change. Styling only the existing unnamed figures leaves the redundant totals and legend crowding untouched.

## Interface

1. **Header.** Keep the title, scope chooser, timestamp, Refresh/Cancel, Settings, and Add in the fixed header. The scope title takes remaining width and truncates with a tooltip for the full name; title/actions/timestamp keep their space. Header actions retain native button behavior and gain keyboard focus and explicit accessibility labels. When a fetch-fallback notice exists, an info button after the scope chooser opens its text in a popover; partial aggregate coverage, errors, and refresh progress stay visible in the content. Existing empty, stale, error, partial, and refreshing states retain their messages.
2. **Hero.** In `MomentumHero`, show visible labels `SOURCE CHURN` and `NET SOURCE CHANGE` above their figures, with `last N closed days` context in the hero. Churn is the dominant high-contrast number, net change and its sparkline use neutral ink even when positive; a plus sign means lines added minus deleted, not a quality verdict. Each keeps its existing sparkline, open-day trailing segment, help definition and hover readout. Ensure its absolutely positioned hover card still clears the summary beneath it. No metric or trend calculation changes.
3. **Composition.** Render `snapshot.metrics` differently without changing the public model: latest `Source` total followed by `Code` and `Tests` as components; show `Docs` on its own line. The source total must not appear additive with all three other numbers. Use native text ink for values and small keyed marks for chart series, not colored numerals alone. Preserve `--` when unavailable and the aggregate cohort semantics from the snapshot.
4. **Charts.** Keep `SourceVolumeChart` and `MonthlyChurnChart` together in the scroll view and preserve axes, hover rows, series, and current partial period. Headings read `Lines over time` and `Monthly activity`, without explanatory subtitles. Put both legends beneath their charts; the source legend names Code, Tests, and Docs, and the activity legend uses a compact single row of `+`/`-` entries grouped by kind. Accessibility labels retain the full added/removed names and the chart descriptors explain the docs band below zero. Do not change the chart's numeric domain or fake negative documentation data.
5. **Accessibility.** Add an `AXChartDescriptorRepresentable` for each detailed chart using the existing timeline, with labels and series values corresponding to actual counts, not invented negative docs; verify Apple's Swift Charts integration in the Xcode SDK and with VoiceOver. Use a categorical date axis and speak the report's documentation values without applying the visual inversion; the summary explains that the band is drawn below the baseline for separation. Unexpected negative report values are reported as such rather than called positive. Apple's `AXChartDescriptorRepresentable` and `accessibilityChartDescriptor` compile with the installed Xcode SDK in a standalone probe. Maintain accessible summary labels for the hero's sparklines. The chart hover layer remains pointer-driven but does not gate data for assistive technology. No new data table UI or separate chart model is added.
6. **Footer.** Preserve Remove and Quit behavior. Removing a workspace also deletes its saved report, so a reassuring confirmation that only mentions source files would misrepresent the consequence. A truthful confirmation is a separate UX fix with its own review and real `LSUIElement` activation test, not part of this diff.

## Sequencing after critic

The independent final round requested decomposition, not another critique. First land a SourceVolumeChart accessibility descriptor and inspect the AXAudiograph's Docs values and separation summary in the running debug preview; spoken VoiceOver output and a live popover scope switch were not verified in the pilot. If that mapping misleads, use a positive Docs strip instead of scaling the descriptor pattern. Apply the validated chart representation to MonthlyChurnChart in the next slice, then ship the visual hierarchy changes as a separate PR. The visual acceptance condition is that the headline question in Outcome is answerable from visible text without hover, both charts remain reachable without switching modes, and their legends, header actions, and bottom content render unclipped at 430 points in dark and light.

A standalone SwiftUI probe suggested `ScrollView.frame(maxHeight:)` would self-size. In the running app it instead accepted a shorter parent proposal: the content measured taller than the viewport and still clipped the activity chart. The view now measures its inner stack with `onGeometryChange` and sets the viewport to that height, capped below the screen's visible height with room for the fixed header/footer.
